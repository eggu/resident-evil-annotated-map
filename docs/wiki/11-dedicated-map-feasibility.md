# 지도 전용 화면 추가 가능성

2026-10-19 설치 EXE/모드 소스 조사 및 후보 구현. 새 전용 화면의 실제 게임 출력 검증 전입니다.

## 결론

기존 상태창 지도를 연 상태에서 단축키로 전환하는 확대 지도 모드는 추가 가능합니다. 현재 후보에는 탐색 중 M으로 진입하는 경로도 구현했습니다. 게임의 원래 메뉴 task와 정지/복귀 처리를 재사용하며, 실제 실행 검증은 필요합니다.

## 재사용할 경로

- `0x43bf40`: `MAP_STATE[1]`이 0이면 지도 로더 `0x43bfb0`, 1이면 갱신/입력 경로 `0x43c330`을 호출합니다. 기존 지도 상태를 유지하면 층 전환과 방문 상태 처리를 재사용할 수 있습니다.
- `0x43c3e9`: `MAP_STATE[3]`에 따라 열기/표시/닫기 상태로 분기합니다. 현재 `map_draw_hook`은 지도 sprite의 sx/sy가 0x1000인 안정 상태에서만 오버레이를 표시합니다.
- `0x43c7c0`: 지도 sprite 세 장과 현재 방 강조를 그립니다. 기존 sprite에는 원점·확대율이 있고 `0x4422e0`이 이를 받아 그립니다. 원본 좌표와 오버레이 좌표를 같은 변환으로 확대해야 합니다.
- `src/re1_map.c`: 방문/획득/문 해제/캐릭터 필터, 지도 타일, 표시 단축키를 재사용할 수 있습니다. 2026-10-19 실제 게임에서는 타일 슬롯의 +0x208..+0x218 좌표·크기를 명시해야 그리기 명령이 생성되는 것을 확인했습니다.

## 필요한 변경과 검증

1. 기존 지도에서만 동작하는 확대 토글과 닫기 처리. 확대 종료 시 원본 sprite 상태 복원.
2. 지도 배경과 현재 방 강조를 동일한 원점/배율로 확대. 방·열쇠 좌표도 같은 변환 적용.
3. 상태창 테두리·인벤토리를 가리는 배경과 그리기 순서 확인. 현재 지도 함수 뒤에도 상태창 명령이 생성되므로 지도 함수만 생략하는 것으로 전체 화면이 되지는 않습니다.
4. 층 전환, 지도를 소지하지 않은 지역, 열기/닫기 애니메이션, 키보드/컨트롤러, 한글 자막 모드와의 공존을 실제 실행에서 검증.

## 현재 구현

- 상태창 지도에서 `7`로 전환. 기본 지도 창에서만 키를 처리하며 열기/닫기 애니메이션에서는 해제합니다. 탐색 중 M으로 바로 열고 M/취소로 닫는 경로도 구현했습니다.
- 원본 128×100 지도 TIM 형상을 생성 데이터에 포함하고, (32,4)에서 2배 확대합니다. 지형은 기존 방문 비트, 현재 방, 획득 플래그를 적용해 그립니다. 전체 320×240 논리 화면을 불투명 배경으로 덮습니다.
- 주석과 지형은 같은 변환을 사용하며, 글자 자체의 표시 크기는 유지합니다. 지도명은 y=206, 범례는 y=216부터 두 줄입니다. 작은 상태창 지도에는 아이템·문서 이름을 생략하고 범례를 y=110부터 5열 × 2행으로 배치합니다.
- 8배 원본 글자에 맞춰 논리 32×32 / 텍스처 256×256 타일을 사용합니다. 전체 화면은 80개 타일이며 합성이 바뀔 때만 업로드합니다.
- 전용 화면의 지도 타일은 Marni 깊이 400 / ordering 25, 배경은 깊이 416 / ordering 26으로 설정합니다. 깊이 0에서는 표식 미표시였고 400 보정 후 사용자가 실제 확대 표시를 확인했습니다. 다른 게임·자막 명령에는 적용하지 않습니다. 원본 sprite를 수정하지 않으므로 원래 화면 복귀 시 복원할 sprite 상태가 없습니다.
- 네이티브 검증 범위: 전환/닫기/포커스, 11개 층, 미방문 바닥 숨김, 기존 패널 경계, UV 배율 및 전경 깊이 명령. 실제 GPU 출력·인벤토리 가림·원래 층 전환 입력·성능 확인은 남아 있습니다.

## M 진입과 이동

- `0x48d0a2` / `0x48d0aa`의 카메라 갱신 후, 원본 `0x48d0b2` 메뉴 진입 검사 직전에 M을 검사합니다. 원래 검사와 같은 플레이어 busy, 조작 허용 0x140, 메뉴 플래그와 게임 모드 2를 확인한 뒤 기존 raw 메뉴 요청 0x800을 보냅니다. 원본 검사 코드는 변경하지 않습니다.
- `0x40b5ac`의 메뉴 task 초기화 호출 후 직접 진입 요청이 있는 경우에만 지도 선택/substate 0만 설정합니다. `0x43ca60` / `0x42c6b0` 로더는 원본 첫 메뉴 프레임의 `0x40b62c..0x40b643` 경로가 실행하도록 두며, 초기화를 앞당겨 직접 호출하지 않습니다.
- `0x40b96b`의 UI 갱신에서 직접 진입한 화면만 M/취소를 원본 종료 `0x40b9e0`으로 연결합니다. 원래 정리 함수 `0x40ba50`의 호출 세 곳에서 직접 진입/전용 화면 플래그를 해제합니다.
- 방향키는 지도를 ±96 논리 픽셀 범위에서 옮깁니다. Home은 중앙 복귀입니다. y=204 위의 지도 부분만 잘라 이동하고 제목·범례는 고정합니다. 이동 자체로 텍스처를 다시 합성하거나 업로드하지 않습니다.
- 불투명 배경은 별도 캐시 타일 하나를 전체 창 크기로 그립니다. 원본 렌더러의 RGB-zero 색상 키를 피하고자 RGB(9,9,9)를 사용합니다. 실제 배경 가림은 사용자 실행 확인 전입니다.

## 2026-10-19 M 무반응 후 수정 후보

- 실행 중 탐색 스냅샷은 Status_flg=0x90800008, 게임 모드=2, 조작 허용=0xffff, 별도 전환 상태 0xC384EB=0이었습니다. 초기 구현의 상태값 ==2 제한은 원본 메뉴 검사에 없던 잘못된 제한이므로 제거했습니다. 이전 후보를 상태값 3으로 실행한 테스트에서도 무반응이 재현됐고, 수정 테스트는 실제 상태값 0을 사용합니다.
- 요청 플래그는 다음 카메라 프레임에서 지우지 않고 원본 메뉴 초기화가 소비하도록 유지합니다. 임의의 전환 상태값으로 요청 수명을 판단하지 않습니다.
- 직접 보기에서는 원본 작은 지도 그리기와 상태창 UI 그리기를 생략합니다. 정상 첫 메뉴 프레임이 지도를 초기화한 다음 UI 갱신 위치에서 전용 화면만 한 번 그립니다. 기존 메뉴의 pause/정리 경로는 유지합니다.
- live 단축키 제한 제거 후 원래 상태창이 열리는 것은 확인됐지만, 진단 감시 중 검은 화면 및 프로세스 종료가 발생했습니다. 하드웨어 감시는 해제했고 재사용하지 않습니다. 새 초기화 순서 및 전용 UI 경로는 재시작 후 확인이 필요합니다.


## 2026-10-19: M 표시 확인 후 원본 층 선택 복원

- 사용자가 M 전용 지도 표시를 확인했습니다. 전체 화면 지도 이동은 불필요하다고 요청하여 pan/Home 처리를 제거했습니다.
- 전용 배경은 원본 `Map_blue.tim`의 별도 팔레트/텍스처를 사용하며 주석 타일의 빈 곳을 투명 처리합니다. 범례 하단은 불투명 패널입니다.
- 취소 입력의 원본 호출(0x40b6ff)을 분기하여 전체 지도 → 층 선택 → 닫기로 동작합니다. M은 바로 닫습니다.
- 층 선택은 원본 `0x43bb00`의 로더/입력/방문 여부/지역·층 UI를 호출합니다. 해당 UI 명령만 (33,32) 기준 2배로 확대하고 깊이392/order24로 주석 앞에 표시합니다. 원본 UV와 텍스처는 유지합니다.
- `0x43bbd0`가 읽는 원본 게임 앞으로/뒤로/좌우 입력 비트를 그대로 사용하므로 재할당 키 및 패드가 같은 경로를 사용합니다. 별도 방향키/Enter/Tab 읽기를 추가하지 않습니다. 원본 확인 비트0x4000으로 선택한 지도를 표시합니다.
- 전용 모드에서는 일반 인벤토리 입력 함수 호출(0x40b6d6)만 생략하여 확인 입력이 상태창 항목을 실행하지 않게 합니다. 일반 상태창 경로는 원본으로 위임합니다.
- 새 배경/지역·층 전환/컨트롤러의 실제 실행 확인은 아직 필요합니다. 실행 중 메모리 패치/디버거는 사용하지 않습니다.


## 2026-10-19: 선택 화면 제거, 반복 배경 및 제출 수 감소

- 사용자 보고: 전용 화면 저프레임, 늘린 격자, 원본과 다른 투명도, 층/위치 선택 화면 미표시. 사용자는 별도 선택 화면을 제거하고 지도에서 바로 층/장소를 바꾸도록 지시했습니다.
- 원본 `0x43bbd0(MAP_STATE)`를 전용 프레임에서 실행한 뒤 선택된 페이지를 그립니다. 앞으로/뒤로 = 층, 좌/우 = 장소이며 `Key_rep 0xC3F8E0`의 게임 입력을 읽습니다. 기존 native +C/+D/+16 방문·소지 가능성 판정을 그대로 사용합니다. 확인 입력이나 물리 방향키를 따로 읽지 않습니다.
- 전용 모드에서만 `0x43be2a -> 0x43be40` 선택 UI 그리기를 생략합니다. 상태창의 일반 입력 `0x40b6d6 -> 0x465a10`과 인벤토리 그리기 `0x40b6ed -> 0x488310`도 전용 모드에서만 생략합니다. 일반 상태창에서는 원본 함수로 위임합니다. 취소는 원본 메뉴 닫기 경로를 사용합니다.
- `Map_blue.tim`의 8×8 원본 셀을 512 텍스처에 반복하고 (0,0)..(319,239)를 같은 크기로 샘플링합니다. 지형은 별도 저해상도 타일을 (32,4)..(287,203)에 2배로 그립니다. 글자 타일은 원래 8배 해상도를 유지합니다.
- 원본 지도 sprite attr0x51000000, 배경 attr0x41000000에서 format8bpp 비트를 제외한 blend0x50000000/0x40000000를 각각 적용합니다. 원본 `0x4409d0` 및 `0x4b2834` 테이블은 모두 alpha128/256을 생성합니다. 배경/지형을 합치지 않아 레이어 간 합성 순서도 유지합니다. 깊이/ordering: 배경416/27, 지형408/26, 주석400/25.
- 타일을256에서512로 묶어 주석은 최대20명령, 지형/배경 각1명령입니다. 빈 타일은 생략하며 정지 프레임에서 재업로드하지 않습니다. 실제 FPS 향상은 아직 측정하지 않았습니다. Native TIM 로더와 마니 UV의512 타일 실제 GPU 수용은 실행 확인이 필요합니다.


## 2026-10-19: 512 UV 반복 및 행동 입력, 이벤트 기반 캐시

- 사용자 스크린샷에서 512 주석 타일이 256 단위로 반복됨을 확인했습니다. 네이티브 CPU 명령 테스트만으로 실제 텍스처 샘플링을 보장할 수 없었던 사례입니다. 256 TIM/UV 0..255 경로로 복귀합니다. 내부 해상도는4배, 폰트15/13/13으로 조정하여 기존 논리 글자 크기를 유지합니다. 배경만 256px +64px의 두 명령으로 채우며 지도/주석은 반복하지 않습니다. 최대23개 명령입니다.
- 원본 selector는 `0xC3F8E0`의 물리 방향 트리거를 읽습니다. `0x483390`은 별도로 게임 행동 held/edge를 `0xC38710/12`에 계산합니다. 행동 low nibble(앞1/좌2/뒤4/우8)을 selector high nibble로 임시 변환한 뒤 원본 값을 복원합니다. 입력 직전 `0x43bd30`으로 현재 층 이동 가능 상태를 준비합니다. 원본 방문·소지 제한을 해제하지 않습니다.
- 이전 매 프레임 signature에는 전체 표식의 marker_visible/방문·획득·문 비트 읽기가 있었습니다. 이를 제거했습니다. 메뉴 진입/정리, 페이지 변경, 옵션 변경, 일반 지도 원점 변경에만 compose합니다. 입력이 없으면 native selector/eligibility 함수도 호출하지 않습니다.
- 표식 조건은 다시 지도를 열 때 새로 계산하므로 탐색 중 획득/문 해제/방문 변경을 반영합니다. 지도 안에서는 일시정지 상태를 전제로 합니다. 단순 정지 프레임에는 캐시된 타일만 제출합니다.
- 테스트는 정지3프레임에서 방문/획득/문 배열 메모리 읽기0회 및 업로드0회, 행동 입력만으로 층/장소 전환, 원본 raw 입력 복구, 길게 누르기, UV255 상한을 검사합니다. 새 후보의 실제 FPS와 패드/반복 제거는 사용자 실행 확인이 남아 있습니다.
