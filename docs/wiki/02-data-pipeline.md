# 데이터 추출과 검증

모든 단계는 `tools/`의 스크립트로 재현됩니다(게임 파일은 읽기만 함).

1. `rdt1.py`, `extract.py` → `data/rdt.json`: `jpn/Stage1..7/ROOMsrrp.RDT` 320개(4바이트 더미 파일 제외)의 init/main SCD를 BioRand 명령 길이표로 해석. 문(`door_aot_set`), 아이템(`item_aot_set`), AOT(`aot_set`/`aot_reset`, SCE 종류), 플래그 `set`, 그리고 각 명령을 감싸는 `if`/`else` 조건을 기록. 파일 끝 자리 0=크리스, 1=질(질 파일에만 배리의 락픽이 있음으로 확인).
2. `map_shapes.py` → `data/map_rooms.json`: TIM CLUT 블록으로 방 마스크·문 표시 픽셀·라벨 기준점(내부에서 가장 깊은 점) 추출.
3. `match_highlights.py` → `data/slot_names.json`: evilresource 층 지도(게임 지도 확대본)를 TIM과 맞추고 방별 빨강 하이라이트를 슬롯에 투표. 저택·기숙사·연구소·정원·동굴 전 슬롯 이름 확보.
4. `match_rooms.py` → `data/room_match.json`: 내용물(아이템)과 문 연결로 지도에 없는 방(헬기장 등) 이름 보완.
5. `fit.py` → `data/room_xform.json`: 원작 지도에는 월드→지도 변환이 없으므로, 방마다 문 AOT 중심을 그 방 슬롯의 노란 문 표시 군집에 맞춰 평행이동+90° 회전(거울상 제외)을 맞춤. 페이지별 축척 0.00095–0.00124 px/단위, 문이 둘 이상인 방의 중앙 오차 약 0.5px. 투영점이 방 밖이면 가장 가까운 방 픽셀로 이동.
6. `build_data.py` → `data/annotated.json`: 위 결과 + `data/curated.json`(한국어 방 이름, 퍼즐 목록, SDK 표에 없는 아이템 이름) 통합.
7. `gen_wiki.py`, `preview.py` → 이 위키 표와 `img/page-NN.png`.

## 한계

- 이벤트로 생성되는 아이템(사각형 0, 예: 시계 뒤 방패 열쇠 일부, 동상 파편 속 푸른 보석)은 방 중심에 표시.
- 조건부 배치(`if ck`)는 조건과 무관하게 표시하고, 획득 플래그로만 숨김. `ck` 핸들러(`0x417f50`)는 `flag XOR 값`을 돌려주므로 SCD 값 0 = "플래그가 켜져 있음"입니다(`rdt.json`의 `is_set`).
- **2026-10-19 수정:** 처음 버전은 evilresource를 방 이름 매칭에만 쓰고 아이템 목록 대조를 하지 않아, 배리가 건네주는 산성탄·락픽, 교체 상태 아이템, 다른 캐릭터용 변형이 지도에 나왔습니다. 이제 `tools/verify_items.py`가 방·캐릭터별로 대조합니다([12](12-item-verification.md)).
- 방 변환: 문 1개짜리 방은 회전·대응 문이 모호해서, 문 일치 수 + 방의 다른 AOT가 방 모양 안에 들어오는 비율로 고릅니다. 게임 지도는 방마다 축척이 달라서(예: 개인 서재는 실제보다 좁게 그림), 문이 노란 표시에 그대로 맞는 경우에 한해 방 상자에 맞춘 가로·세로 축척(`fit=bbox`)을 씁니다. 방 AOT의 80% 미만만 방 안에 들어오는 방은 118개 중 7개(대부분 50–67%)로 줄었습니다(이전 28개).
- 퍼즐 해결 상태 플래그는 아직 연결하지 않음(방문 범위에서 항상 표시).
- 이벤트 SCD(오프셋 8)는 별도 ISA라 해석하지 않음. 퍼즐 목록은 외부 자료로 보완.
- 지도 좌표는 정적 추정이며 게임 화면 확인이 필요.

## 이름 배치(2026-10-19, RE2 지도 모드 규칙)

`tools/label_layout.py`는 RE2 지도 모드의 `generate_room_names.py` 규칙을 옮긴 것입니다.
- 좁은 방부터 배치합니다. 이름 상자의 90% 이상이 그 방 모양 위에 놓이면 방 안에 둡니다. 벽 여백 2px → 1px → 0px 순으로 시도하고, 무게중심에 가장 가까운 자리를 고르며, 이미 놓인 이름과 겹치지 않게 합니다.
- 안 맞으면 두 줄로 나눠 다시 시도합니다.
- 그래도 안 맞으면 방 가장자리에서 시작하는 가장 짧은 수직·수평 연결선을 그어 빈 공간에 둡니다. 연결선은 벽을 지날 수 있지만 다른 방은 지나지 않습니다. 빈 공간이 없으면 벽선 위까지 허용합니다.
- 상태 화면(1배, 글꼴 13×S/4)과 전체 지도(2배, 글꼴 15×S/4; S=8 텍셀/PSX 픽셀), Apple SD Gothic Neo Medium + 1텍셀 외곽선는 각각, 언어별로 따로 배치합니다. 아이템 이름(전체 지도 전용)은 아이콘 옆에 두고, 방 이름·연결선·아이콘을 피합니다.
- 전체 지도는 페이지마다 실제 지도 내용의 범위를 y 18–208 영역의 가운데에 둡니다. 제목은 위(y 4), 범례는 아래(y 212)입니다.
- 전체 지도의 방 색은 원작 지도 CLUT를 씁니다: 벽 `0x5ad6`, 문 `0x12dc`, 테두리 `0xe1`, 바닥 `0x81a4`(반투명). 일부 슬롯은 +4 `0x83f4`, +5 `0x279`입니다. 현재 방 +1..+3은 빨강 `0x1F`, 남은 아이템 방은 모드의 호박색입니다.
- 미리보기: `build/layout-<status|full>-<page>-<lang>.png`.
- 이름(방·아이템)과 연결선은 별도 타일 층에 그리고 70% 보이게(INI `NameOpacity`=70) 그립니다. 그리기 명령 +44 값은 비쳐 보이는 비율이라 1−불투명도(0.3)를 씁니다(2026-10-19 실제 게임 확인: 0.7을 넣으면 약 30%만 보임). 아이콘·범례·제목은 불투명입니다.

## 전체 지도 RE2 스타일(2026-10-19)
- 제목: 왼쪽 위 (10, 8)에 왼쪽 정렬된 큰 세리프 두 줄(영문 Times New Roman Italic 대문자, 한글 AppleMyungjo).
- 범례: 왼쪽 아래 "DISPLAY STATUS/표시 상태" 아래 `[n] 이름: 켬/끔` 2열.
- 층·구역 이동 화살표: 초록색, 0.4초마다 밝게(85% 보임)·어둡게(35% 보임) 바뀌며 깜박이고 사라지지 않습니다. 화면 가장자리에서 2–5px 띄웁니다. 원작 선택기(`0x43bbd0`) 규칙대로 실제로 이동 가능한 방향에만 표시합니다. 위/아래는 `MAP_STATE[12]` bit0/1, 좌/우는 `[13]` 구역 비트이고, `[13]&8`이면 `0x43bd08`/`0x43bd18` 표를 씁니다.
- 캐릭터 화살표: `Pl_work 0xC351B4`(RE1-Mod-SDK `PLAYER_WORK`)의 `Pos_x 0xC351E8`, `Pos_z 0xC351F0`, `Cdir_y 0xC35228`을 현재 방(`0xC386F1`)의 맞춘 변환으로 지도에 옮깁니다. 16방향, 화살표와 같은 방식으로 밝게·어둡게 깜박임. 방향: 전진 이동(`0x410170`)은 (속도, 0, 0)을 `RotMatrix(0, Cdir_y, 0)`(`0x455a80` → `0x433350`, 각도 부호 반전, sin/cos 표 `0x4b640c`/`0x4b6410`)로 돌려 더합니다. 그래서 앞쪽은 (cos, −sin)입니다. 2026-10-20에 실제 코드를 에뮬레이션해 확인했습니다: 0 → +x, 1024 → −z, 3072 → +z. 처음 쓴 (sin, cos) 가정은 90° 어긋났습니다. `ArrowRotation`은 보정용으로 남겨 둡니다.
- 방 윤곽선: 벽은 0.75px 두께의 불투명 선, 문은 원래보다 작은 금색 사각형으로 고해상도 층에 그립니다. 바닥은 반투명이고, 벽 칸은 이웃 방 색으로 채웁니다. 벽은 그 층 지도를 얻은 뒤에만 보입니다. 원작 로더 `0x43c001`→`0x43cec0`가 `Flg_7` 비트 0x7C+n(페이지별 0,1,–,2,3,4,4,–,5,5,–)으로 판정하고, 지도가 없으면 CLUT 7–12를 지우는 것과 같은 규칙입니다. 범위 [8]이 모든 방이면 지도가 없어도 보입니다.
- 상태 화면 지도는 아이콘만 표시하고(이름 숨김), 범례는 짧은 이름(`0 전체` … `9 EN`)으로 지도 칸 안 아래쪽 한 줄(x 32–137)에 둡니다.

## 2026-10-19 수정 3
- **SCD if/else 길이:** `if`/`else`의 길이 바이트는 명령 시작 위치부터 셉니다. 블록은 `pos + len`에서 끝나고, 거기에 `else`나 `endif`가 옵니다(전체 RDT 기준 `if` 2770/2774, `else` 749/749). 처음 버전은 2바이트를 더해 `else`를 바깥 `if`에 붙였고, 그 때문에 조건이 서로 모순되는 기록이 67개 있었습니다. 지금은 0개입니다.
- **아이템 배치 조건:** 아이템마다 캐릭터별로 그 아이템을 놓는 SCD `if ck` 조건을 담고, 실행 중에 계산합니다. 놓는 기록 중 하나라도 지금 조건을 만족해야 표시합니다. 예: 질의 마스터 키(연구소 B4 메인 연구실)는 `Flg_1[91]`이 꺼져 있을 때만, 크리스는 `Flg_1[192]`가 켜져 있을 때만 놓입니다. `ck`가 아닌 조건은 판정할 수 없어 통과로 봅니다.
- **퍼즐 해결:** 34개 중 15개를 판정합니다. 보상 아이템을 가져갔거나(획득 플래그가 꺼짐) 코드로 확인한 플래그로 판단합니다(식당 엠블럼 홈 `ck(1,167)`, 엠블럼 석상 `ck(1,164)`). 크랭크, 배터리, 메달, 문 암호 등 판정 근거가 없는 퍼즐은 계속 표시됩니다(`curated.json` `solved_when`).
- **구역 화살표:** 왼쪽(`KEY_LEFT`=8)을 누르면 원본 raw 0x80 경로로 구역 번호가 1 커집니다. 그래서 저택에서는 왼쪽, 기숙사에서는 오른쪽 화살표가 나옵니다.
- **벽과 문:** 맵 1픽셀당 2텍셀인 불투명 텍스처 한 장에 그립니다. 벽은 1px 선이고, 문은 맞닿은 문 픽셀 덩어리마다 2px 두께의 짧은 금색 막대 하나입니다. 이전에는 벽을 고해상도 타일에 그려 타일 대부분이 갱신됐고, 텍스처 업로드가 100개를 넘었습니다. 이제 한 페이지에 최대 60개(모든 방 표시 기준)이고, 바뀌지 않은 타일은 다시 올리지 않습니다(FNV 해시 비교).
- **잠긴 문 열쇠 배치 규칙:** RE1 HD 리마스터 지도 모드(`gen_labels.key_sides`, `re1_mapnames.c`)와 같습니다. 문 표시의 법선 방향으로 비켜 놓고, 가로 문은 위·아래, 세로 문은 좌·우입니다. 문의 방향은 벽으로 정합니다. 두 방이 각자 절반씩 그리는 노란 문 표시를 페이지 전체의 문 픽셀로 이어 붙인 뒤, 벽이 표시의 위·아래에 닿으면 세로 문, 좌·우에 닿으면 가로 문입니다. 노란 표시의 모양은 방향이 아니라 문 종류를 나타냅니다. 정사각형이면 양문, 직사각형이면 외문입니다. 2026-10-19 기준 전체 21개 중 결정 못 한 문은 0개이고, 정할 수 없으면 빌드를 멈춥니다. 키 배치는 `gen_assets.py`가 마커 46개를 스스로 검사합니다. 세로 문(세로로 긴 표시)은 `|문| (열쇠) [이름]` 한 줄로 두고, 왼쪽이면 거울처럼 뒤집습니다. 가로 문(가로로 긴 표시)은 문, 열쇠, 이름 순으로 세로로 쌓고, 위쪽이면 뒤집습니다. 회전은 하지 않습니다. 같은 문을 두 방이 각각 기록하고 각자 표시를 그리므로, 2.5px 안의 같은 열쇠 문은 하나로 합칩니다(예: 피아노 바 문의 락픽 2개). 문 양쪽 배치를 모두 만들어 두고, 실행 중에 문의 두 방 중 방문하지 않은 방 쪽을 고릅니다. 둘 다 방문했거나 둘 다 안 했으면 목적지 쪽입니다. 방문 범위(1)에서는 두 방 중 하나라도 방문했으면 표시합니다.
- **아이콘과 이름 간격:** 이름 위치를 고를 때 자기 아이콘과의 겹침은 계산하지 않습니다. 그래서 대부분 아이콘에 바로 붙고(0–1텍셀), 이전처럼 2px 밀려나지 않습니다.
- **문 표시:** 그 층 지도를 얻어 벽을 보여 줄 때는 방문하지 않은 방의 문도 함께 그립니다. 바닥 색만 방문한 방에 칠합니다.
- **M 바로 열기:** 맵 초기화(`0x43ca60`) 직후 선택기 갱신(`0x43bd30`)도 호출합니다. 그래야 층·구역 이동 가능 바이트 [12]/[13]이 첫 화면부터 채워집니다. 이전에는 불러온 직후 첫 화면에 화살표가 없었습니다.
- **범위 [8]:** 세 단계를 돌아갑니다(INI `Scope` 1/2/3).
  - 1 방문한 방: 방문한 방만 표시합니다.
  - 2 공개된 방: 방문한 방과 층 지도를 얻은 층의 방(`Flg_7` 비트 0x7C+n)을 표시합니다.
  - 3 전체: 모든 방을 표시하고, 지도가 없어도 벽을 그립니다.
  - 방 이름은 범위 1에서도 공개된 방까지 표시합니다.
- **전체 지도의 문:** 벽선을 이어 가는 금색 선분(3px 두께)으로, 문 너비만큼 그립니다. 양문(정사각형 표시)은 원래 지도처럼 정사각형으로 그리고, 외문은 벽선 위의 선분 하나로 그립니다. 벽 방향은 원래 지도의 벽 픽셀로 정하므로, 층 지도가 없어 벽을 숨긴 때도 맞습니다.
- **배치 순서(2026-10-20):** 아이콘, 열쇠, 아이템·퍼즐 이름을 먼저 아이콘 옆에 둡니다. 방 이름은 그것들을 장애물로 보고 피해서 방 안에 넣거나, 넣을 곳이 없으면 방 밖에 두고 선으로 잇습니다. 그래도 자리가 없으면 마지막 수단으로 다른 방 바닥 위라도 이름·아이콘과 겹치지 않는 곳에 둡니다.
- **해상도:** 게임 1픽셀당 8텍셀(S=8), 오버레이 타일은 256×256(게임 32px)입니다. 2026-10-20에 S=16과 512 텍스처를 시도했지만, REbirth가 스프라이트 UV를 256에서 되감아 타일마다 왼쪽 위 1/4만 2×2로 반복돼 화면이 깨졌습니다. 텍스처는 256을 넘을 수 없습니다.
- **아이콘 가림 허용:** 이름이 다른 아이콘을 절반 넘게 가리지 않으면 허용합니다. 장애물로는 아이콘의 가운데 70%×70%(넓이 약 49%)만 씁니다. 이전에는 아이콘 전체에 여백을 더하고 PSX 칸 단위로 올림해, 실제보다 훨씬 큰 장애물이 됐습니다. 그래서 온실 이름이 방 밖으로 밀리고 호랑이 석상실 퍼즐 이름이 멀리 밀렸습니다.
